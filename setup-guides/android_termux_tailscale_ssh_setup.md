# Termux Tailscale Userspace SSH Target Setup Guide
- This guide describes how to configure an unrooted Android device running Termux to function as both a Tailscale node and a SSH target.
- Standard Tailscale installations require root privileges to create a system-level network TUN interface. 
- In an unrooted Android environment, you must force Tailscale to run in userspace networking mode. 
- Because userspace mode isolates the network from the main operating system routing tables, inbound and outbound traffic must be bridged explicitly using `SSH` `ProxyCommand` and Tailscale's internal application netcat engine (`tailscale nc`), completely bypassing tailscale serve.

## Environment Specifications
The procedures in this guide have been validated using the following environment versions:
| | Version|
|-|-|
|OS Version|Xiaomi HyperOS 2.0.16.0.UMZMIXM|
|Android Version|14 (Build UKQ1.240624.001)|
|Termux Application Version|0.119.0-beta.3 (Installed via the official [GitHub](https://github.com/termux/termux-app/releases) release APK)|
|Tailscale Core Version|1.66.1 (arm64 static Linux binary)|

## 1. Install Base Packages
Open your Termux application and install the required core packages, networking diagnostic tools, and text editors.
```bash
pkg update && pkg upgrade -y
pkg install openssh vim rsync iproute2 lsof -y
```

## 2. Deploy the tailscale-termux-cli Solution
To simplify pathing and ensure correct command execution limits inside Termux, deploy the custom CLI helper utility directly from its source repository.
```bash
curl -fsSL https://raw.githubusercontent.com/bropines/tailscale-termux-cli/main/remote-install.sh | bash
```
Termux-services may need to be installed
```bash
pkg install termux-services
```

## 3. Launch the Tailscale Daemon (Session 1)
- Unrooted Android environments cannot bind network services to system-level system paths.
- You must start the background daemon process manually by passing the user-space modifier flag and specifying a writeable file path destination within the Termux filesystem space.
- Open a dedicated Termux session or a tmux pane, and execute the following command:
    ```bash
    tailscaled \
    --statedir /data/data/com.termux/files/home/.tailscale \
    --socket /data/data/com.termux/files/home/tailscaled.sock \
    --tun=userspace-networking
    ```
    - `/data/data/com.termux/files/home/.tailscale`: This is a user-defined directory to store Tailscale profiles and state configurations. You can rename this folder or map it to any other location where your user account has write permissions.
    - `/data/data/com.termux/files/home/tailscaled.sock`: This is a user-defined file path and name for the communication socket. If you alter this socket file path or file name, you must reference your updated path exactly in all subsequent commands.

### Background Task Preservation
---
- Pull down your Android platform notification shade and tap Acquire wake-lock (or run `termux-wake-lock` directly in a terminal shell).
- This prevents Android from placing Termux processes into a deep sleep state when the device display turns off.- Keep this terminal session running `tailscaled`.

## 4. Node Provisioning and SSH Configuration (Session 2)
Open a second Termux tab or split-pane session. Leave the first window running the active `tailscaled` daemon.

### 1. Authenticate to the Tailnet
---
Run the following registration command, pointing explicitly to your custom socket path file to generate your unique device pairing URL:
```bash
tailscale --socket /data/data/com.termux/files/home/tailscaled.sock up
```
Navigate to the provided web link in your browser to approve and sign the Android device into your Tailscale Admin Console.
### 2. Configure and Fire Up OpenSSH
---
- Set password for your Termux instance
    ```bash
    passwd
    ```
- Start the SSH server
    ```bash
    sshd
    ```
    Note: This command does not print anything to the terminal. 
- Determine your exact system user ID
    ```bash
    whoami
    ```
    - This returns a ID string similar to u0-a309, which is a dynamic, unique user signature generated by Andriod. 
    - This identifier is the username that will be used for SSH later.
- Verify that the OpenSSH process is successfully bound and listening on its unprivileged port (8022):
    ```bash
    netstat -tlnp | grep 8022
    ```

## 5. Construct Client SSH Configurations
- Because user-space networking cannot inject routes directly into the local Android OS networking stack, outbound connections from a device running user-space tailscaled cannot resolve Tailscale IPs natively.
- Instead, traffic must be piped directly through Tailscale's internal netcat facility (`tailscale nc`) using a `ProxyCommand`.

### A. Connecting from an External Laptop/PC to your Termux Target
---
- If your client computer or laptop is connected to the tailnet using the official Tailscale application (which operates with system-level network routing), you do not need a ProxyCommand.
- You can connect directly using standard SSH parameters.
- Add the following block to your computer's local SSH config file (~/.ssh/config):
    ```text
    Host termux-tablet
        HostName 100.119.31.112
        User u0_a328
        Port 8022
    ```
- Note
    - `termux-tablet` is a customizable reference tag. You can rename it freely.
    - `100.119.31.112` represents the dynamic Tailscale IP address assigned to your target Android node. Verify on the tailscale admin console
    - `u0_a328` represents your dynamic Android user signature on your target node. Verify by running `whoami` in termux
- To connect: Execute the native command from your laptop terminal:
    ```bash
    ssh termux-tablet
    ```

### B. Connecting from Another Termux Device (Device 2) to your Termux Target (Device 1)
---
If you are initiating the connection from a secondary Termux environment (Device 2) where `tailscaled` is running in user-space mode with a custom socket, a `ProxyCommand` is strictly required so the client knows how to route the traffic out of its isolated environment.
1. Create or open the SSH config file inside your initiating Termux environment (Device 2):
    ```bash
    mkdir -p ~/.ssh && vim ~/.ssh/config
    ```
1. Inject the following block, ensuring the `--socket` flag explicitly points to your custom user-space runtime socket:
    ```text
    Host termux-tablet
        HostName 100.119.31.112
        User u0_a328
        Port 8022
        ProxyCommand tailscale --socket /data/data/com.termux/files/home/tailscaled.sock nc %h %p
    ```
    Note: `/data/data/com.termux/files/home/tailscaled.sock`: The exact path where Device 2 hosts its isolated background daemon socket.
1. To connect: Execute the command from your Device 2 Termux terminal:
    ```bash
    ssh termux-tablet
    ```

## 6. File Sync Implementation
Because your custom `ProxyCommand` configurations are managed natively by the SSH environment, file system sync utilities will function over the userspace mesh automatically without extra variables.
### Option 1: Copying Single Files via SCP
---
To send a file from your `termux-tablet` to `termux-phone`, run this in the `termux-tablet` device
```bash
scp /path/to/local/file.txt termux-phone:/data/data/com.termux/files/home/
```
To pull a file from `termux-phone` to `termux-tablet`, run this in the `termux-tablet` device
```bash
scp termux-phone:/data/data/com.termux/files/home/photo.jpg ./
```
Note: `termux-tablet` and `termux-phone` is are user defined SSH host configurations that must exist on SSH client devices that wishes to interact with the SSH servers. 

## Option 2: Using rsync (Best for large directories or resuming broken transfers)
If you are transferring large sets of data, directories, or media files over Tailscale, `rsync` is highly superior to `scp` because it can compress data and resume if the network drops.

1. Install rsync on both your tablet and phone:
    ```bash
    pkg install rsync -y
    ```
2. Sync a folder from your tablet to your phone:
    ```bash
    rsync -avzP /path/to/tablet/folder/ phone:/data/data/com.termux/files/home/target_folder/
    ```
   The -avzP flags keep file attributes intact, compress the data stream, and show a real-time progress bar.
